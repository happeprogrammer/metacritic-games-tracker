# Принятые решения

Короткий список «что выбрали и почему».

1. **Node.js 24 без сторонних библиотек.** HTTP, SQLite (`node:sqlite`), криптография, тесты (`node:test`), `fetch` есть в самой платформе. Меньше поверхность для сбоев и уязвимостей, образ маленький, сервису хватает ~100 МБ памяти.
2. **Внутренний JSON-интерфейс Metacritic вместо разбора вёрстки.** Им пользуются страницы самого сайта; ответы стабильнее, чем HTML, и приходят в 30 раз легче. Единственное, что берётся с HTML, это блок New Releases на главной (порядок игр по заданию). Ключ интерфейса публичный, лежит во фронтенде сайта; при смене сервис покажет красный статус источника.
3. **День считается в настраиваемом часовом поясе** (по умолчанию Москва). Курсор выбора привязан к дню: новый день начинается заново автоматически, обработанные сегодня игры пропускаются, продолжение ленты точное (смещение растёт на число реально просмотренных элементов).
4. **Один прогон за раз, без «догоняющих» серий.** После простоя сервис делает один запуск и перестраивает сетку расписания. Прерванный прогон возвращает свои игры в очередь повторов.
5. **Очередь задач в базе.** Задачи на резюме переживают перезапуск, повторяются с нарастающей паузой, а «ИИ недоступен» не считается ошибкой самой задачи.
6. **Резюме с доказательствами.** Модель обязана приложить к каждому пункту дословную цитату из отзывов; код проверяет, что цитата реально есть в отзывах этой же группы (критики или игроки). Пункт без подтверждения отбрасывается, доля отброшенных пишется в журнал. Проверено вживую: слабая модель, придумавшая цитаты, была отклонена, цепочка перешла к следующей.
7. **Цепочка бесплатных провайдеров** с суточными потолками, охлаждением после 429, отключением при отказе в доступе, повтором при кривом JSON и журналом каждого вызова. Для OpenRouter разрешены только модели `:free`. Если лимиты кончились, данные собираются дальше, резюме ждут в очереди; игры с наибольшим числом отзывов обрабатываются первыми.
8. **Рассуждающие модели.** Бесплатные модели OpenRouter могут потратить весь бюджет токенов на «размышления» и вернуть пустой ответ. Размышления отключаются в запросе; если модель этого не разрешает, запрос повторяется с большим бюджетом.
9. **Безопасность по умолчанию.** Весь сервис за входом (роли viewer и admin), пароли только хешами (scrypt), подписанная cookie, лимит попыток входа, защита от подделки запросов (заголовок + проверка Origin), строгая политика безопасности контента без inline-скриптов и стилей, внешние тексты выводятся только как текст (XSS), параметризованные SQL-запросы, ограничение размера запроса.
10. **Жёсткие лимиты контейнера** (память без свопа, процессор, процессы, файловая система только для чтения, ротация логов), потому что сервис живёт на общем маленьком сервере и не должен ему мешать.
11. **Управляемость.** Одна таблица настроек определяет значения по умолчанию, проверку и форму в админке; изменения вступают без перезапуска и пишутся в журнал действий.
